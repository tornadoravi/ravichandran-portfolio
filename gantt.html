01 / Overview

Before the timeline,
make the setup clear.

A Gantt view starts with a relationship between tasks, dates, and the fields that describe them.

In Analytics+ for Power BI, that relationship spans two places: the Power BI field well and the visual’s Pivot data configuration. The setup needs to explain both where data is added and how each field is used.

This case follows Gantt selection, the data-mapping help state, and the populated workspace. It is separate from my PowerTable work in Microsoft Fabric →.

02 / Gantt entry

Give project work
its own starting point.

Make the intended view explicit before asking people to configure it.

The landing screen presents Gantt alongside Charts, Cards, Tables, and Storyboard. In the supplied state, Gantt is selected and grouped under Projects, distinguishing the task-and-timeline route from general analysis and presentation.

The field instruction and inactive Build chart control communicate that setup is still required. Choosing a view is a starting point, not evidence that the underlying data is ready.

03 / Data mapping

Bridge the field well
and the visual.

Explain the destination, not just the missing information.

The Data-mapping dialog shows date fields moving into Gantt/Network fields in Power BI. Its instruction explicitly names the Gantt fields destination, making the requirement more concrete than a generic request to add data.

The next layer is role assignment inside Pivot data: start date, end date, progress, and other Gantt-specific roles. Adding a field to Power BI and assigning its meaning within the visual are related but distinct actions.

POWER BI / FIELD WELL

Make the fields available

Add the relevant task and date data to the visual’s field parameters.

ANALYTICS+ / PIVOT DATA

Give each field a role

Map available fields to the start, end, progress, and display configuration.

04 / Timeline workspace

Keep the task detail.
Add the time context.

The configuration and the resulting view should be understandable together.

The populated workspace places Pivot data and field-role settings on the left, with task rows and timeline bars alongside them. The date axis spans years, quarters, and months, while task names and group labels remain visible in the grid.

The screenshot shows actual-start, actual-end, and progress mappings. The planned-date, milestone, and connector slots are also visible, but their presence is not a demonstration of configured behavior. The walkthrough stays focused on the setup and timeline states shown.

05 / Reflection & references

Clarity begins
before the chart.

The setup experience is part of the visualization experience.

The sequence makes three questions visible: Which view am I creating? Where should the fields go? How do those fields become a timeline? The interface connects those questions through a dedicated entry, mapping guidance, and configuration beside the resulting view.

One next refinement: align the entry instruction’s “Chart fields” wording with the mapping guidance’s “Gantt fields.” That is a terminology recommendation from these screens, not a change shown as implemented.
