Supplied design / Two panel states

A clear start. A manageable list.

The empty state explains the next action. The populated state introduces search and row controls. These are supplied states, not a recorded creation sequence.

01 / Empty backlog

Explain the absence.
Offer the next step.

“No Task Available” is paired with an instruction and + Add Task. The panel gives an explicit starting point instead of leaving the empty area unexplained.

02 / Populated backlog

Keep the list compact.
Keep actions nearby.

Backlog List (1) contains T0011, with edit and delete icons. Search and + New Task remain above the list; the task form itself is not supplied.

03 / Same second state · Change controls

A visible item is not proof of a saved record.

The second screen also shows Preview Changes (1), Save to Database, and Discard Changes. This crop preserves that distinction between the current view and a save action.

No save confirmation or database result is supplied. The change count does not establish which fields changed or prove that T0011 was persisted.

Design rationale / Reading the supplied interfaces

Support the work before it reaches the schedule.

  1. 01

    Make the first action explicit.

    The empty-state message and Add Task button work together. Loading, permission, and error states are not supplied and should not be confused with this empty state.

  2. 02

    Retain creation alongside management.

    The populated panel keeps New Task, search, and row actions together. The identifier-only row is compact; task recognizability at scale remains a review question, not a measured finding.

  3. 03

    Distinguish local changes from persistence.

    Preview, save, and discard controls expose separate choices. The screenshots do not establish validation, conflict handling, or success feedback after saving.

Scope, delivery & source limitations

My contribution: backlog sits within the confirmed end-to-end PowerTable Gantt UX/UI scope, including developer handoff and implementation review. This does not imply Microsoft employment or production-code ownership.

Evidence: two supplied screenshot states, presented as three native-resolution crops. The first provides the empty panel; the second provides the one-item list and change toolbar. The creation form and interaction between these states are not supplied. Product controls and values are unchanged.

Limits: the screenshots do not establish T0011's underlying dates, task-form fields, search behavior, deletion confirmation, drag-and-drop scheduling, permissions, save persistence, or a completed scheduling flow. This is a screenshot-led design case, not an interactive backlog application.

Sources: Microsoft Learn overview and Resource layout task-management guide reviewed November 10, 2026. The guide supports the backlog concept and resource-layout workflow, not every detail of this task-based Gantt panel or its release status. No independently verified feature-specific customer review, usability result, or impact metric is included.

Handling: the original attachments are marked Confidential/Internal Only. Crops exclude account/workspace chrome and the surrounding project task grid. Cropping is not publication clearance. This remains a local preview; confirm permission before public use.

Platform: the unchanged Fabric icon identifies the platform, not endorsement. Azure DevOps backlogs, Intelligence charts, and Analytics+ Gantt are not substituted as feature evidence.
