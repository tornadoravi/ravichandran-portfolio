Design rationale / Interface analysis

Separate what changes, retain the context.

The original screens keep the schedule beside the editor. These focused crops expose the settings without repeating the full workspace.

  1. 01

    Group settings by the object being edited.

    Four tabs distinguish working context, milestone symbols, color, and labels. The trade-off is that settings across tabs cannot be compared at once.

  2. 02

    Separate task styling from resource summaries.

    Data Color and Label give bars and summary bars distinct controls. Their different meanings remain visible in the configuration hierarchy.

  3. 03

    Keep a consistent panel frame.

    Search, tab navigation, close, and Reset to Default Styling stay in place across the four states. Search results and reset behavior are not supplied.

02 / Milestone

Keep the symbol and its fill distinct.

Shape displays a flag icon; Fill shows a purple swatch. This focused tab exposes two separate appearance choices without mixing them into timeline settings.

The shape picker and any upload interaction are not shown. This is a configuration state, not evidence of an applied milestone change.

03 / Data Color

Differentiate tasks from summaries.

Bars has Color by set to All with a blue Fill. Summary Bar has a separate brown Color swatch.

Separate groups make the two styling targets explicit. This state does not show a column-based color configuration or a conditional threshold.

The supplied screens are tab states, not a before/after sequence or verified live-preview behavior.

04 / Label

Control the information on the bar.

Enable Data Label and Adaptive label are On. Based On is Auto; the bar-label font size is 12, with separate Text Color and Background Color controls.

Summary Bar has its own font size of 12 and a black Text Color swatch. Task and summary labels have independent styling groups.

No responsive-label behavior, contrast result, or readability improvement is established by this still image.

Scope, delivery & source limitations

My contribution: this case belongs to the confirmed end-to-end resource Gantt UX/UI scope, with developer handoff and implementation review. It does not imply Microsoft employment or production-code ownership.

Evidence: four supplied Edit Resource tab states, cropped locally at native resolution. Resource names and account/workspace chrome are excluded; panel controls, spacing, colors, and values are unchanged. These are related settings, not mandatory workflow steps.

Configuration versus rules: the Edit Resource panel configures scheduling context and component appearance. Condition-based highlighting belongs to the separate Conditional Formatting case. No conditional-rule builder is shown in these four attachments.

Limits: no search result, expanded picker, changed setting, reset confirmation, persistence test, or before/after result is supplied. The Timeline state's +6 selections are not individually visible. Documentation also describes settings and actions not present in every supplied state; these are not added to the screenshots or attributed as unseen designs.

Validation: no independently verified feature-specific customer review, measured usability improvement, or business-impact metric is included. Documentation supports the capability, not release verification of this exact design. The portfolio is not an interactive settings application.

Handling: the originals are marked Confidential/Internal Only. Cropping is not publication clearance. This remains a local preview pending permission for public use.

Sources: Microsoft Learn Customize Resource Layout and Planning overview, reviewed November 10, 2026. The unchanged Fabric icon identifies the platform, not endorsement.
