Business case

Keep the work, time,
and capacity connected.

Support planning decisions without separating the task from its wider context.

PowerTable combines no-code, writeback-enabled data management with planning experiences in Microsoft Fabric. The objective is a coherent relationship between task detail, time, and resource availability.

Product context / Microsoft Learn

What is planning in Fabric?

Microsoft Fabric is the wider data platform. Planning brings budgets, forecasts, scenarios, and operational data into that governed environment. PowerTable is its structured-data and data-application component; this case focuses on my planning UX/UI work, not the entire suite.

  1. The platform

    Microsoft Fabric

    The data and analytics environment in which the planning experience lives.

  2. The planning suite

    Planning in Fabric

    Planning, PowerTable, and Intelligence capabilities connect plans, operational data, and insights.

  3. My product context

    PowerTable

    No-code table applications with an Excel-like editing experience, writeback, and project-planning capabilities.

A product relationship, not a mandatory setup sequence. Current Microsoft documentation calls this component “PowerTable sheets.” The supplied screen uses “PowerTable.” Neither the suite description nor the Microsoft icon implies ownership of all Fabric planning capabilities.

02 / Gantt experience

The task and timeline.
In the same picture.

Make the relationship between the work and its timing easier to follow.

The design scope included the Gantt canvas, task creation and editing, timeline and timescale controls, column configuration, navigation, baseline comparison, effort tracking, and export.

The intent was to support movement between task detail and the broader plan. A connected canvas gives task information and timeline context a shared place, while configuration makes room for different planning needs.

PLAN CONTEXT

Gantt / Supplied configuration screen

Start with the fields.
Make their roles clear.

The setup connects source columns to the meaning a planning view needs.

The earlier Layout Configuration screen keeps Gantt selected in the view navigation and groups mappings under Tasks, Time Entries, Resource, and Cost. In the visible Tasks tab, start date, end date/duration, and Task ID carry required markers.

STRUCTURE

Dates, identity, hierarchy

Parent ID and Multiple Column Hierarchy are alternative hierarchy choices. Milestone, progress, dependency, and estimated effort have their own mapping controls.

DISCLOSURE

Core first, more when needed

Filter columns and the expanded Additional mapping options area separate further settings from the core roles. Reset and Next remain visible in this earlier screen; the new supplied states use Save.

The information banner describes a configuration shared across Gantt, Resource, Calendar, and Kanban layouts. That message explains the intended relationship; the supplied evidence does not verify cross-view synchronization or the completed save behavior.

03 / Resource Gantt

Beyond the task.
The people doing it.

A plan needs a view of resources as well as a view of time.

My resource Gantt scope included workspace and navigation, summary bars, resource assignment, backlog, time-tracking interactions, and capacity and workload visibility.

The design intent was to help people connect outstanding work with resource availability and see how assignments fit into a broader plan. This describes the purpose of the design, not a measured improvement in allocation or productivity.

Exploration, not a shipped claim

Earned-value and baseline-planning work for resource Gantt was exploratory. It is separate from the baseline-comparison design scope of the Gantt experience and is not presented as released functionality.

04 / Cross-tab contribution

Structured data.
Flexible perspectives.

Alongside the Gantt work, I contributed to cross-tab layout and data configuration: rows, columns, measures, contextual settings, and the presentation of summarized and detailed information.

The intent was to make the relationship between configuration and the resulting view understandable, so people can shape a useful perspective on their data without losing its structure.

Reflection

Different views.
One connected system.

The core design challenge was keeping the connections visible.

Tasks depend on time. Assignments depend on capacity. Data views depend on configuration. Designing across those layers means considering transitions and shared context, not only individual screens.
