# Ravichandran V — Product Designer portfolio

A responsive React portfolio with a shared editorial theme across Home, About, and every active case study, an illustrated portrait, a 3D-style paper mascot, minimal product cards, and screenshot-led case studies. Selecting Soundroom plays the user's supplied **Pudhu Vellai Mazhai / Roja** MP3 without changing the chosen appearance. React and React DOM are bundled locally; there are no runtime external requests, portfolio analytics, or stock photography. Saving local files alone does not deploy or push them.

## Preview

Requires Node.js 22.12 or newer.

```sh
npm install
npm run build
npm start
```

Open **http://127.0.0.1:4173**. The production preview serves only the built `dist/` output and binds only to the local machine. Set `PORT` to use a different port. After changing frontend code, rebuild and reload the page; HTML requests refresh the compiled-asset allowlist so new bundles work without restarting the server. Server-code changes still require a restart. `npm run dev` starts the Vite development server instead; JavaScript-disabled checks should use the pre-rendered production build.

## React architecture

All 19 active routes are real React pages in `src/pages/*.jsx`, not HTML strings injected into a React wrapper. `src/Portfolio.jsx` shares the React header and theme provider. `src/Header.jsx` owns menu/character state and navigation; `src/ThemeContext.jsx` and `src/SoundroomControls.jsx` own palette, playback, volume, error, and cancellation state. Browser-only animation, native screenshot inspection, section tracking, and diagram effects live in `src/portfolio-effects.js`, initialized and cleaned up through the React lifecycle.

Vite splits the page components into separate bundles. The production build pre-renders every route using `src/entry-server.jsx`; `src/main.jsx` hydrates that markup in the browser. Existing `.html` URLs, native links, section bookmarks, supplied content, and screenshot bytes are preserved. Pre-rendered content and native navigation remain available without JavaScript. The archived standalone portrait remains a separate, unchanged offline document.

With JavaScript, `src/navigation.js` progressively enhances ordinary same-tab links between active portfolio pages. The shared React shell and one native audio element stay mounted, so opted-in music, volume, and playback position survive navigation. Page components remain split bundles; local HTML provides the destination's title, description, and body classes. Page effects are cleaned up and reinitialized for the new content. Back/Forward restore reading position and expanded evidence, and route changes focus the main content and announce the new title. Native same-page bookmarks, modified clicks, new tabs, downloads, external links, and non-portfolio URLs retain their browser behavior. Loading errors are logged and fall back to the original document navigation; hard refreshes and leaving the site still stop playback.

The shared header keeps the same dimensions and brand/contact alignment when switching pages at the same viewport width. Page-specific content widths are intentional: the floating pill header is narrower than the reading column, and About uses its own profile width. Styles are imported once, in base/mapping/editorial order, to prevent cross-page CSS cascade differences. Walkthrough styles also load with the shared shell so prerendered reading content does not briefly expose hidden player text before hydration. `tests/react-shell.spec.js` verifies matching dimensions and error-free hydration across all pages.

## Automatic publishing with Netlify

The repository includes `netlify.toml`: build command **`npm run build`**, publish directory **`dist`**, and Node.js 22. In Netlify, sign in, choose **Add new project → Import an existing project → GitHub**, authorize access to `tornadoravi/ravichandran-portfolio`, and select **`main`** as the production branch. After the first successful deployment, future pushes to `main` automatically rebuild and publish the site while continuous deployment remains enabled. Saving local files alone does not publish them.

The build publishes the pre-rendered React pages and compiled bundles plus the public assets in `site-files.js`. The local production server uses the same public boundary. It never publishes the repository root, private `career-ops/`, environment files, development scripts, tests, or dependencies. It preserves supplied asset bytes and generates Netlify `_headers` with the local server's content-security, content-type-sniffing, and referrer protections, including the standalone portrait's separate policy. No single-page-app catch-all redirects are needed: the portfolio consists of real pre-rendered HTML routes. Run **`npm run test:build`** to check the output boundary, source bytes, stale-file cleanup, headers, and production server responses.

Focus is the default listening mode for new visitors. An explicitly selected Soundroom listening mode can persist within the same tab, but restoring it never starts music without a user action.

Home uses one static headline: "I’m a product designer making complex products easier to use." It stays unchanged with or without JavaScript and across motion preferences; there is no rotation timer or decorative text entrance.

## Automatic publishing with GitHub Pages

In the repository's **Settings → Pages**, select **GitHub Actions** as the source. `.github/workflows/deploy-pages.yml` installs the locked dependencies with Node.js 22, runs the production build, and deploys **only `dist/`** on pushes to `main` or a manual workflow run. Do not publish the repository root: its HTML files are Vite source entries, not runnable production pages.

The workflow obtains the base path from GitHub Pages configuration. Vite's `SITE_BASE_PATH` configures compiled assets, and `src/site-path.js` applies that same base to native links, images, downloads, audio, and bookmark redirects in both prerendered and hydrated markup. Client navigation recognizes only routes within that base. Root-hosted local previews and Netlify keep `/` by default; build a project-site version with `SITE_BASE_PATH=/ravichandran-portfolio/ npm run build`. `npm run test:pages` builds and serves that subpath in an isolated test server, checking every route with and without JavaScript, local asset loading, bookmarks, and navigation without restarting audio. Its cleanup restores the default build even after an assertion fails. Do not run it concurrently with root-preview browser checks: the temporary subpath build uses the same `dist/` directory.

GitHub Pages does not apply Netlify's `_headers`. Prerendered React documents therefore also include the existing content-security policy as a meta tag. The HTTP-only `frame-ancestors` directive is omitted from that meta policy; the local server and Netlify retain their full HTTP headers.

Its sample script connects ideas instead of listing "first, then, finally." These are generation instructions, not proof of improved naturalness: compare samples by listening before replacing the walkthrough voice.

