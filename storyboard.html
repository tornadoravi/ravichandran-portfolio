Business case

Turn visual building blocks
into a useful report.

Support different starting points within one authoring experience.

Some report authors begin with a template; others need a custom layout or an empty board. Reusable starting points and flexible composition need to work together.

Design rationale

Pain points & solution highlights.

Authoring challenges grounded in the supplied interfaces, paired with their design responses.

  1. 01 / Pain point

    Authors do not all begin the same way.

    A blank report, a predefined layout, and an existing template represent different authoring intentions.

01 / Overview

From individual visuals
to report composition.

Storyboard connects the choice of starting point, report structure, and editing context into one authoring experience.

My work included storyboard enhancements, presentation mode, annotations, slideshow interactions, Text-to-Visual, and PowerPoint visualization templates, within Analytics+ at Lumel Technologies.

The walkthrough follows report creation, layout, template entry points, and the canvas. Chart Wizard has a separate case study →.

Scope & evidence

Product screenshots provide context, not independent ownership of every displayed feature or template. Presentation contributions are described separately from the authoring screenshots.

02 / Starting point

Choose how
to begin.

The entry screen presents four routes: Auto create – report, Custom layout, Choose template, and Blank report. Each option pairs a label with a short explanation of the starting point it offers.

This separates different authoring intentions before the user enters the canvas: an automatically generated report, a configured structure, an existing template, or an empty workspace.

03 / Custom layout

Connect configuration
with the report structure.

The Custom layout screen uses three regions: Elements Configuration, a central Preview, and Pivot data – KPI. The visible controls include KPI, chart, and table counts, trellis toggles, navigation placement, comments, and a viz-data-ink ratio slider.

The preview places the selected KPI region within the larger report, while the adjacent data area shows category and measure fields. This creates a visible relationship between the element being configured, its place in the layout, and its data context.

Reset and Apply sit at the bottom of the workspace, keeping the confirmation controls separate from the configuration regions.

04 / Templates

Browse a starting point
or bring an existing one.

The Choose template screen distinguishes Explore template store from Import templates. The import route includes a drag-and-drop instruction, while Explore provides a route to the template catalogue.

The public Analytics+ store organizes its offerings into standalone templates, dashboard templates, visual components, and data apps. The supplied store screenshot shows search, category filters, and preview cards that provide context for browsing reusable assets.

The store is included as product-ecosystem context. Individual dashboards, community assets, and the store itself are not presented as separate projects I owned.

05 / Blank report route

An empty board.
A visible next action.

Blank report is another starting route, separate from custom-layout configuration and template selection. Its empty state explains that no elements are present and directs the user to the insert control.

The left rail exposes Pivot data, Properties, Advanced, and Action, while board tabs remain available along the bottom. The authoring workspace is visible before report content has been added.

05.1 / Populated authoring state

Compose the report.
Keep its structure visible.

The populated workspace shows a report containing KPI cards, three bar charts, a slicer, and detailed table data. A layer hierarchy on the left exposes top-bar elements, cards, charts, and a table within the report structure.

This view follows the starting-route examples in the case study so the reader can see the contrast between setup and a composed report. It is a supplied authoring-state example, not a recorded sequence of every action taken to create the report.

06 / Related presentation work

Beyond authoring.
Communicating the story.

A composed report is the foundation for communicating insights in a deliberate sequence.

My contributions extended to presentation mode, annotations, and slideshow interactions. That communication layer now has a dedicated Annotations, Comments & Presentation case →.

The six images in this case study show storyboard authoring and its template ecosystem. They are not presentation-mode or slideshow screenshots, and no specific presentation behavior or customer result is inferred from them.

07 / Reflection

Keeping the structure
and the story connected.

The authoring context matters as much as the final report.

A useful starting point, a readable layout, and a visible relationship between elements and data give report composition a clearer structure.
